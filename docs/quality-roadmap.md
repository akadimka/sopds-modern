## 2. Убрать недетерминизм многопроцессности — не начато

Порядок обработки файлов в Pass1 (`ProcessPoolExecutor`) сейчас влияет на
выбор между равнозначными вариантами при консенсусе (порядок слов в
имени автора, дробные номера подсерий типа "2.1"/"2.2") — то есть два
прогона одной и той же библиотеки без единого изменения кода иногда дают
разные (хоть и одинаково "корректные") результаты. Это уже вносило шум
при верификации фиксов этой сессией (нужно было отличать реальные
регрессии от этого шума через baseline-vs-baseline diff).

**Идея фикса:** зафиксировать порядок обработки файлов перед раздачей по
воркерам (сортировать) и/или сделать финальный tie-break в консенсусе
детерминированным (например, по алфавиту первого варианта), а не "кто
первый обработался".

**Риск:** может задеть много мест в `pass1_read_files.py`/`pass4_consensus.py`
— нужна та же дисциплина full-library diff, что использовалась весь
сентябрь, ПЛЮС новый regression fixture-набор (пункт 1) для быстрой
проверки уже известных кейсов.

## 3. Задокументировать приоритет источников — не начато

Принцип "папка > имя файла > метаданные" (плюс саб-случаи: вложенная
подпапка = свой датасет для подсерии, арки строятся из имён файлов
только когда НЕТ папочного сигнала) сформулирован в разговоре с
пользователем, но нигде не записан как единый источник правды в коде.

**Идея:** таблица/константа в docstring `regen_csv.py` или отдельный
`docs/series-priority.md`, на который можно ссылаться при разборе новых
кейсов вместо повторного выведения правил заново.

## 4. Ревизия конфиг-патчей (`author_surname_conversions` и т.п.) — не начато

**Требует домашней библиотеки пользователя** (~80К файлов) — точечные
записи в `src/fb2_data/settings/app_settings.json` (например,
`author_surname_conversions`) накапливались как затычки под конкретные
книги. Нужно пройтись по списку и проверить, какие из них всё ещё
актуальны/нужны, а какие устарели (книга переименована, автора больше
нет в библиотеке и т.п.).

**Как выполнять:** запустить `python scripts/build_regen_fixtures.py
<путь_к_домашней_библиотеке>` НЕ для сборки fixture (это отдельная
задача — искать НОВЫЕ краевые случаи полным прогоном regen_csv/
find_groups по всей библиотеке, см. README.md в п.1), а затем отдельно
пройтись по `author_surname_conversions`/аналогичным спискам в
`app_settings.json` и для каждой записи проверить, есть ли в текущей
библиотеке файл, к которому она реально применяется.
