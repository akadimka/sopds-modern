## 2. Убрать недетерминизм многопроцессности — ✅ Готово

`Pass1ReadFiles.execute()` собирал `records` в порядке ЗАВЕРШЕНИЯ
воркеров (`concurrent.futures.as_completed`), а не в стабильном
порядке — из-за чего последующий консенсус (порядок слов в имени
автора, дробные номера подсерий типа "2.1"/"2.2", капитализация серий)
иногда давал разные результаты между прогонами без изменения кода.

Фикс: `records.sort(key=lambda r: str(r.file_path))` сразу после сбора
результатов в `pass1_read_files.py`. Проверено на полной библиотеке
Test1 (~12000 файлов): два подряд прогона одинакового кода дали
**0 расхождений** (было — десятки на каждую пару прогонов). Diff
против baseline (без фикса) — 172 записи, все относятся к уже
известным категориям недетерминизма (имя автора, капитализация серии,
перестановка дробных номеров), теперь зафиксированы в одно конкретное
значение; данных не потеряно.

## 4. Ревизия конфиг-патчей (`author_surname_conversions` и т.п.) — ✅ Готово

Выполнено на реальной библиотеке пользователя, доступной с этой машины
двумя путями сразу: по SSH (`/mnt/media/Docs/Books` — 50163 fb2, 107 ГБ;
`/mnt/media/Docs/EBookLibrary` — 660 fb2, 2 ГБ) и через сетевую шару
(`\\turnkey\Docs\Books`, см. локальный dev-сервер).

**Как проверялось:** для всех 61 записи `author_surname_conversions`:
1. Точное совпадение ключа с именем папки — 17/61 совпали.
2. Для остальных — присутствие каждого значимого слова ключа в "шапке"
   FB2-файлов (первые 16 КБ — метаданные автора всегда там, до тела книги
   и base64-обложек; полнотекстовый grep по 107 ГБ был бы неоправданно
   долгим). 43/44 подтвердились.

**Результат:** только одна запись оказалась мёртвой —
`"Постельгио": "Постегильо"` — ни одного совпадения ни по одному слову
нигде в текущей библиотеке. Удалена из `app_settings.json`. Остальные 60
записей — реально применяются к существующим файлам, не трогали.

Другие точечные списки в `app_settings.json` (`series_conversions` — 1
запись, `special_series_values` — 1 запись) слишком малы, чтобы
накопить "устаревшее"; `series_folder_blacklist` и подобные — общие
правила, а не патчи под конкретные книги, вне области этого пункта.

## 5. Анализ полной библиотеки на аномалии парсинга — 🔄 продолжается, передано на другую машину

**Зачем.** ИИ-агента нельзя поселить на сервер (старый 2-ядерный AMD E-350
не тянет современный Node.js/Claude Code), а вручную разобрать логику
regen_csv/fb2_compiler на 50163 файлах нереально. План: прогнать
`regen_csv`/`find_groups` разом по ВСЕЙ библиотеке (не на сервере — на
машине с бóльшим числом ядер), получить CSV, и уже по CSV эвристиками
находить подозрительные случаи для точечного разбора — тем же способом,
каким были найдены и закрыты кейсы Bykov/Panov/Аржанов ранее.

**Сделано (2026-09-01/02, на Windows-машине через `\\turnkey\Docs\Books`):**
- `regen_csv` по всей библиотеке: **49519 записей**, 114.8 мин.
- `find_groups`: **6651 групп** для компиляции, 80.25 мин (после фикса
  ниже; до фикса процесс казался зависшим — CPU был около нуля).
- Побочно найден и исправлен реальный прод-баг (закоммичено, `eaf3341`):
  `_extract_year_from_fb2`, `_extract_date_from_fb2`,
  `_precompiled_range_from_content` (`fb2_compiler.py`) и хелпер в
  `precache.py` делали `path.read_bytes()` (весь файл) и потом отрезали
  первые N КБ — на сетевой шаре это гоняло по сети мегабайтные файлы
  (обложки) ради чтения только заголовка. Исправлено на частичное чтение
  (`f.read(N)`). Баг актуален и для прод-компиляции на сервере, не только
  для анализа.

**Результаты анализа (НЕ в git — `.gitignore`'нуты, переносятся вручную
между машинами; на момент передачи уже скопированы на вторую станцию):**
- `src/fb2_data/csv/full_library_records.csv` — все 49519 записей после
  regen_csv (author/series/genre и т.д. по каждому файлу).
- `src/fb2_data/csv/full_library_groups.csv` — 6651 групп компиляции
  (author, series, n_books, volume_range, series_complete,
  order_determined, alphabetical_order, part_count, file_paths).
- Из records: **17929 записей** имеют `proposed_series`, но НЕ попали ни
  в одну группу — это не обязательно баг (могут быть реальные синглы),
  но именно тут стоит искать пропущенные дубликаты/расхождения в
  написании автора или серии.

**Дальше (не начато) — предложенные эвристики для сужения списка:**
1. Группы с `order_determined=False` и/или `alphabetical_order=True` —
   слабая уверенность в порядке томов, компилятор просто разложил по
   алфавиту вместо реального номера.
2. Аномальные `volume_range`/`part_count` на автора (например один автор
   с кучей мелких групп по 2 книги вместо одной большой серии —
   подозрение на несведённые варианты написания серии).
3. 17929 ungrouped-with-series (см. выше) — отфильтровать по частоте
   автора/серии, чтобы найти те, где явно "распалась" одна серия на
   несколько написаний.
4. Записи со слабым `author_source`/`series_source` (например
   `filename`-only без подтверждения метаданными) на фоне большого
   объёма книг этого автора в других папках.

Дальше — как обычно: по каждому найденному кейсу разобраться в первопричине,
исправить, проверить на реальных данных, закрепить регрессионным тестом в
`tests/integration/fb2parser_core/` (см. README.md там), задеплоить.

**Найдено и исправлено (2026-09-02, применяя эвристику 3 и точечный разбор
`ungrouped-with-series` — реальные fb2-файлы недоступны с этой машины,
проверено на синтетических BookRecord, см.
`tests/integration/fb2parser_core/test_author_series_consensus.py`):**

- **Баг №1 (некорректный):** `series_processor.apply_author_consensus()`
  требовал "≥50% high-priority записей за автора-консенсус", но при
  ОДНОМ high-priority файле в папке 100% от одного голоса тривиально
  проходили порог. Папка-антология "Серия - «Скандинавская линия»\
  Скандинавская линия «НордБук»" (45 файлов, 33 разных реальных
  metadata-автора) содержала ровно 1 файл с filename-уровня сигналом
  (книга самого Сьона) — и её автор навязывался всем остальным 44
  файлам с другими настоящими авторами (Альвтеген, Биргиссон, Буман и
  т.д.). Исправлено: требуем ≥2 high-priority голосов, иначе не
  доверяем консенсусу. Легитимный 2+-голосный консенсус продолжает
  работать (проверено отдельным тестом).
- **Баг №2 (косметический, узкий):** `_postcheck_series_folder_blacklist()`
  обрезал префикс `"Серия - «"`, но не парную закрывающую `»` — серия
  оставалась вида `"Колычев. Лучшая криминальная драма»"` с висячей
  кавычкой. Единственный такой случай во всей 49519-записевой
  библиотеке (подтверждено полным grep перед фиксом). Исправлено:
  обрезаем и закрывающую кавычку, когда она есть; вложенные
  самостоятельные пары кавычек (`«Приключения «Икс»»`) не трогаем.
