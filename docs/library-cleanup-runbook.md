# Чистка библиотеки (шаг 3) — порядок выполнения на сервере-сборщике

Инструкция для сессии Claude на **сервере-сборщике** — той машине, где
библиотека собирается (fb2parser, синхронизация, автокомпиляция) и откуда
она копируется на сервер сайта (sopds-modern-2). Контекст и все решения
пользователя — `docs/series-duplicates.md` (разделы «Решения пользователя»,
«Сделано», «Шаг 3, инструмент»).

## Почему на сборщике, а не на сервере сайта

2026-10-29 перенос жанров запускали на sopds-modern-2 — 47 ошибок
«Permission denied»: файлы библиотеки там принадлежат учётной записи,
которая её копирует, а сайт работает от www-data, и в библиотеку не пишет.
Изменения на копии к тому же затёрло бы следующее копирование со сборщика.
Поэтому чистка — только на сборщике, на sopds-modern-2 изменения приходят
обычным копированием.

## Правила

- Любое изменение библиотеки, коммит, пуш, обновление — только после
  однозначного «да» пользователя (CLAUDE.md). Отчёты (без `--apply`) —
  можно сразу.
- Каждая часть: отчёт → показать пользователю итоги и спорные места → «да» →
  `--apply` → проверить журнал на `✗`.
- Долгие прогоны (компилятор по всей библиотеке — около 40 минут) — в фоне
  и под наблюдением (Monitor: строки журнала, ошибки, завершение процесса,
  «жив» раз в несколько минут). Не оставлять процесс без присмотра.
- Команды запускать от той учётной записи, которой принадлежат файлы
  библиотеки и от которой работает fb2parser на сборщике. Команда сама
  проверяет права до первого изменения: в отчёте «нет прав на запись: N»
  должно быть 0, иначе — выяснить у пользователя, не обходить.

## 0. Подготовка

Все команды `manage.py` ниже — из папки `src` проекта (пути к файлу выбора
даны относительно неё).

1. Узнать у пользователя (если не сказано): от какой учётной записи
   работает fb2parser, где проект и библиотека, как библиотека копируется на
   sopds-modern-2 (rsync с `--delete` или без: без удаления на копии
   останутся лишние копии и старые места перенесённых серий — сказать
   пользователю).
2. `git status` в проекте сборщика: локальные правки общих данных
   (`app_settings.json`, `genres.xml`) — сначала в репозиторий отдельным
   `data:`-коммитом (CLAUDE.md, «Порядок выпуска»).
3. Обновить проект до **v2.39.002** или новее (CLAUDE.md, «Обновление
   проекта»): `git fetch` → `git merge --ff-only origin/master` →
   `migrate` → `compile_messages.py` → `check`. Нужна команда
   `manage.py library_cleanup`.
4. Не запускать во время синхронизации: команда берёт ту же блокировку и при
   занятой выдаст «Идёт синхронизация — повторите позже».

## 1. Серии в нескольких жанрах

Решения: серия переносится в жанр большинства книг; при равенстве — по
выбору, который пользователь утвердил 2026-10-29:
`docs/library-cleanup/genre_choices.tsv` (31 серия, «жанр<TAB>автор /
серия»). Переносятся папки, тег `<genre>` не меняется. Если в целевом жанре
уже лежит файл с тем же именем — остаётся более полная по тексту версия
(правило 1), у каждой своё (разные переводы) — остаются обе.

```
python manage.py library_cleanup --part genres \
    --genre-choices ../docs/library-cleanup/genre_choices.tsv --out genres.txt
```

Проверить отчёт:
- «ждут выбора жанра» должно быть 0. Если не 0 — ключ «автор / серия» на
  сборщике написан иначе, чем в файле выбора (строки `? …` в отчёте):
  дописать в файл выбора строку с ключом как в отчёте и жанром, который
  пользователь утвердил для этой серии; новые серии с равенством — предложить
  жанр пользователю.
- «нет прав на запись» — 0.
- Ожидаемо на сервере сайта 2026-10-29 (сборщик может отличаться): 44 серии,
  40 переносов; на занятом месте замена полной версией — 3 (Гэлбрейт
  «Корморан Страйк», Джайлс «Ворон», Иггульден «Война роз»), удаление лишней
  копии — 4 (Гравис «Визионер», Иггульден «Император», Сиглер
  «Инфицированные», Шаттам «Парижский отдел расследований»), обе остаются —
  2 (Харрис «Цицерон» — разные переводы, Мамбурин «Криндж» — разный текст).

Показать итоги пользователю, после «да»:

```
python manage.py library_cleanup --part genres \
    --genre-choices ../docs/library-cleanup/genre_choices.tsv --out genres_apply.txt --apply
```

Проверить `genres_apply.txt` на `✗` и что повторный отчёт показывает 0
серий в нескольких жанрах, кроме Харриса и Мамбурина.

## 2. Автор «Эльба .Ирина»

Точка из метаданных дала отдельную папку автора (исправлено в v2.38.004 для
новых книг). Слить с «Эльба Ирина»:

```
python manage.py library_rename_author "Эльба .Ирина" "Эльба Ирина"          # отчёт
python manage.py library_rename_author "Эльба .Ирина" "Эльба Ирина" --apply  # после «да»
```

## 3. Решения компилятора по всей библиотеке

Только после шагов 1–2: после переноса группы меняются.

```
python manage.py library_cleanup --part compile --out compile.txt
```

Около 40 минут (разбор ~15–20, поиск групп ~20) — в фоне, под наблюдением.
В отчёте по группам: `СОБРАТЬ`, `ОСТАВИТЬ`, `УДАЛИТЬ`, `НЕ ТРОГАТЬ`,
`ПЕРЕИМЕНОВАТЬ`. Что показать пользователю:
- сводку (групп, файлов на удаление, переименований);
- удаления, где удаляемый файл по имени полнее оставляемого («в 22 книгах»
  против «в 15 книгах») — их быть не должно, кроме случаев, где по тексту
  оставляемый не меньше (2026-10-28: «Бард (в 11 книгах)» длиннее
  «Декалогии в 13 книгах», Клеванский 27/32 — один текст в разной вёрстке);
- переименования — что новое имя не хуже старого;
- крупные замены чужим полным сборником (Панов «Тайный Город (в 41
  книгах)», Суржиков «Полари (в 21 книгах)», Муравьев «Перешагнуть
  пропасть» — так и задумано, решение пользователя).

Сравнение на сервере сайта 2026-10-28 — `docs/series-duplicates.md`,
раздел про `.fb2.zip` и страховки (174 новых удаления в 82 группах, 32
переименования).

После «да»:

```
python manage.py library_cleanup --part compile --out compile_apply.txt --apply
```

Тоже долго — в фоне, под наблюдением. Проверить журнал на `✗ ошибка`.

## 4. Копирование и владельцы на сервере сайта

1. Библиотека копируется на sopds-modern-2 обычным способом пользователя.
2. На sopds-modern-2 (от www-data, `DJANGO_SETTINGS_MODULE=sopds.settings.base`):
   `python manage.py library_owners_check` — отчёт. Записи о владельцах там
   привязаны к путям: у перенесённых и удалённых файлов будут «пути, которых
   нет на диске», у новых мест — «файлы без владельца» (им назначится
   admin). До чистки там уже было 3 755 таких путей и 7 файлов без
   владельца — последствие сбоя 2026-10-29 (лишние копии сборников; до сбоя
   их владельцем был admin, как у всей библиотеки). Показать пользователю
   отчёт; `--apply` — после «да».
3. Каталог OPDS подхватит новые пути при плановом сканировании.
