# Сборники, испорченные дописыванием тома (до v2.35.001)

## Что случилось

До v2.35.001 `fb2_compiler` не узнавал собственный сборник при повторной
сборке. Когда в готовый сборник дописывался новый том (автосинхронизация с
автокомпиляцией или ручная сборка), прежние тома разбирались по главам.
В новом файле вместо «1. Первый», «2. Второй», «3. Третий» оказывались тома
«Содержание», «Глава 1», «Глава 2», «Глава 1», «Глава 2», «Третий», а
оглавление — по главам. Обычно ломается только разбивка на тома, но текст,
лежавший в томе вне разделов `<section>`, старый разбор выбрасывал: от
такого тома осталась одна обложка (так с «Computers - Как один день
(т. 2-5)»). Исправлено в v2.35.001 (`_extract_body_sections`, тест —
`tests/integration/fb2parser_core/test_compiler_extend_own_compilation.py`).
Уже испорченные файлы обновление не чинит.

## Поиск: `scripts/find_damaged_compilations.py`

Скрипт только читает файлы: ничего не меняет, не переименовывает, в базу
не пишет. Нужна только стандартная библиотека Python 3.8+ (venv проекта не
нужен). Читает `.fb2` и `.fb2.zip`.

Признаки (по каждому нашему сборнику — файлу с `<body id="vol_N">`):

| Колонка | Что значит |
|---|---|
| `toc_in_vol` | Внутри «тома» лежит оглавление со ссылками на тома: прежний блок «Содержание» стал томом. Надёжный признак → вердикт **испорчен**. |
| `bad_titles` | Тома с названием «Глава …», «Содержание», «Оглавление». Без `toc_in_vol` → вердикт **проверить**: бывают и настоящие тома с таким названием, смотреть глазами. |
| `modified` | Время последнего изменения файла — примерно когда его последний раз пересобрали. |
| `titles` | Названия томов по порядку, как они записаны в файле. |

### 1. Подготовка

В рабочей копии проекта: `git pull` (скрипт и эта инструкция появились в
коммите после v2.35.001).

### 2. Библиотека на сервере

Ничего на сервере не устанавливать и не менять: скрипт передаётся через
stdin, результат — во временные файлы в `/tmp`, которые потом удаляются.
Запуск — от `www-data` (владелец библиотеки) с пониженным приоритетом.
Папка библиотеки — `root_lib` в `/opt/sopds-modern/src/fb2_data/settings/config.json`
(сейчас `/srv/sopds-books`).

```bash
ssh <сервер-root> 'cat > /tmp/find_damaged_compilations.py' < scripts/find_damaged_compilations.py
ssh <сервер-root> 'sudo -u www-data nice -n 15 python3 -I /tmp/find_damaged_compilations.py \
    /srv/sopds-books --csv /tmp/damaged.csv > /tmp/damaged.txt 2> /tmp/damaged.err; \
    tail -1 /tmp/damaged.txt; wc -l < /tmp/damaged.err'
ssh <сервер-root> 'cat /tmp/damaged.txt'           # весь список; при большом — head/tail
ssh <сервер-root> 'cat /tmp/damaged.csv' > damaged-server.csv
ssh <сервер-root> 'rm -f /tmp/find_damaged_compilations.py /tmp/damaged.txt /tmp/damaged.csv /tmp/damaged.err'
```

`/tmp/damaged.csv` создаётся от имени `www-data`, поэтому `--csv` пишет в
`/tmp`, а не в домашнюю папку. Скрипт по `/srv/sopds-books` идёт минуты: он
читает каждый FB2 целиком.

### 3. Домашняя библиотека

Папка — `library_path` в локальном `src/fb2_data/settings/config.json`.

```powershell
.venv\Scripts\python.exe scripts\find_damaged_compilations.py "<папка библиотеки>" --csv "$env:TEMP\damaged-home.csv"
```

CSV не класть в репозиторий.

### 4. Вывод

```
испорчен   2026-10-23 18:30  томов=6   toc_in_vol=1 bad_titles=5   Автор - Серия (Трилогия).fb2
           тома: Содержание | Глава 1 | Глава 2 | Глава 1 | Глава 2 | Третий

файлов FB2: 3; наших сборников: 2; испорчено: 1; проверить: 0; ошибок чтения: 0
```

Сначала идут «испорчен», затем «проверить», внутри — по времени изменения.
Ошибки чтения (битый zip, нет прав) — в stderr, по строке на файл.

## Что дальше — только с согласия пользователя

Поиск ничего не чинит. Показать пользователю итог и список («испорчен» —
все, «проверить» — с названиями томов). Затем вместе решить, как чинить,
и ничего не менять в библиотеке без его явного «да».

Варианты починки:

1. **Пересобрать из исходных томов**, если они где-то сохранились (резервная
   копия, папка-источник, домашняя копия). Автокомпиляция удаляет исходные
   тома после сборки, поэтому в самой библиотеке их обычно нет.
2. **Восстановить из резервной копии** файл до порчи, затем дописать новые
   тома уже исправленным компилятором.
3. **Восстановить разбивку из самого файла** —
   `scripts/repair_damaged_compilations.py` (ниже).

## Починка: `scripts/repair_damaged_compilations.py`

Как и поиск — только стандартная библиотека, запуск на сервере от
`www-data`, CSV поиска на входе. Без `--apply` только читает и печатает
по каждому файлу «можно» (с раскладкой: том — из скольких глав, первая и
последняя глава) или «вручную» (с причиной). Тест —
`tests/integration/fb2parser_core/test_repair_damaged_compilations.py`
(порча воспроизводится настоящим компилятором).

Что видно в испорченном файле: тело со ссылками на `#vol_N` — прежнее
оглавление (названия и число прежних томов); за ним каждый прежний том
начинается с тела, где одна обложка, а дальше — его главы, каждая отдельным
«томом» с названием главы. Чинится только ясный случай: одно такое
оглавление на n томов, сразу за ним n обложек, у каждого тома есть текст,
и вместе с целыми томами до и после число томов равно диапазону
`<sequence number>`. Главы собираются обратно в тома, глава получает своё
название назад, оглавление сборника строится заново. Перед записью скрипт
сравнивает все абзацы и картинки до и после — текст меняться не должен.

Остальное — «вручную»: файл портился не раз (несколько вложенных оглавлений,
в оглавлении служебные названия), у прежнего тома не было обложки (обложек
меньше, чем томов), томов больше диапазона серии, от тома осталась одна
обложка (текст потерян — только из исходника).

Запись: список одобренных путей (по строке, как в CSV) — в файл,
затем `--apply approved.txt --backup /var/tmp/damaged-backup`. Каждый файл
сначала копируется в `--backup`, затем пишется на место через временный
файл рядом (права — прежние, файл внутри zip — с прежним именем). Путь не
меняется, поэтому учёт владельцев (`ownership.py`, ключ — путь) не
затрагивается и хуки не нужны. Сервер-2 получит файлы ночным зеркалом,
каталог — при следующем сканировании.

Проверено на 2026-10-23: из 43 испорченных — 27 «можно». Восстановленные
тома «Забаненного» совпали с исходными томами из `/mnt/media/Docs/Books`
абзац в абзац (кроме рекламы в конце — другое издание файла).

При любой починке, которая кладёт, двигает, сливает или удаляет файл в
библиотеке, — сообщать через `fb2parser_core/ownership_hooks.py` (см.
CLAUDE.md, «Видимость книг»). После замены файла каталог подхватит его при
следующем сканировании. На сервере — изменения только после «да».
