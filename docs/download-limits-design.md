# Лимит книг: защита от выкачивания библиотеки

Решено 2026-11-27. Код — `src/sopds_web_backend/download_limits.py`, тесты —
`tests/integration/sopds_web_backend/test_download_limits.py`.

## Что считается

Книга «взята», когда её текст ушёл пользователю, любым путём:

| Путь | Адрес / код |
|---|---|
| Скачивание (сайт и OPDS), в том числе zip | `opds:download` (`dl.Download`) |
| Конвертация в EPUB/MOBI/AZW3 | `opds:convert` (`dl.ConvertFB2`) |
| Читалка сайта и OPDS (весь текст на странице) | `web:read`, `opds:view_html` (`dl.render_book_html`) |
| Telegram-бот | `telegram_library.LibraryHandler.deliver` |

Считаются **разные книги за календарный месяц** (`BookTake`: пользователь,
книга, месяц). Та же книга повторно в этом месяце — в любом формате и любым
путём — лимит не тратит: перечитать, скачать в другом формате, открыть в
читалке уже скачанную — можно всегда. Книга в таблице — числом, не ссылкой:
удалённая из библиотеки книга лимит не возвращает. Неудачная выдача (нет
файла, сбой конвертации) книгу не засчитывает.

## Лимиты

- **В сутки** и **в месяц** — личные: `UserProfile.downloads_per_day` /
  `downloads_per_month`, в таблице пользователей рядом с лимитом устройств.
  Пусто — по умолчанию из настроек (`downloads_per_day` = 20,
  `downloads_per_month` = 200; раздел «Лимит книг» на вкладке
  «Пользователи»), 0 — без ограничений.
- **Скорость**: не больше `RATE_BOOKS` (10) новых книг за `RATE_WINDOW`
  (5 минут) — против скриптов, которые укладываются в суточный лимит.
  Не настраивается.
- Сутки и месяц — по местному времени (`TIME_ZONE`).
- Суперпользователь не ограничен; без входа (выключенный `SOPDS_AUTH`) —
  тоже (неизвестно, чей лимит).

## Отказ

- **Сайт**: кнопки «Читать», «Скачать», форматы (любая ссылка на
  `/opds/download|convert|view/<id>/` и `/web/read/<id>/`) перед переходом
  синхронно спрашивают `web:download_check` и при отказе показывают окно —
  переход не происходит (`sopds_main.html`). Синхронный запрос — чтобы при
  разрешении переход остался обычным (новая вкладка, окно приложения PWA)
  без потери «жеста» пользователя. Если проверка не ответила (нет сети) —
  решает сам адрес. Адрес, открытый напрямую, отвечает страницей 429
  (`sopds_download_limit.html`).
- **OPDS (читалка)**: текст с кодом 429 и `Retry-After`.
- **Бот**: сообщение «⛔ …» по-русски.
- `web:download_check` ничего не записывает; чужая и несуществующая книга —
  «можно» (дальше адрес книги ответит 404), чтобы проверка не выдавала,
  есть ли книга.

## Журнал и оповещения

- Отказ — `download_limit_reached` (безопасность, `ok=False`) раз в день на
  вид лимита (сутки, месяц, скорость); считается в «тревогах» в шапке
  суперпользователя.
- Пользователь упирается `REPEAT_ALERT_DAYS` (3) дня подряд —
  суперпользователям в Telegram (их привязанные Telegram и чат
  суперпользователя из настроек), раз в день, в фоне.
- Изменение личных лимитов — `download_limit_changed` (кто → кому,
  «было → стало»); лимитов по умолчанию — «Изменил настройки».
- Сколько взято — в профиле пользователя («Лимит книг») и в таблице
  пользователей.

## Не делали

- Метку пользователя в выдаваемом файле (чтобы найти, с чьего аккаунта
  ушла библиотека) — отложено: файлы отдаются как есть, метка потребовала бы
  переписывать их на лету.
- Автоматическую блокировку аккаунта — решает суперпользователь.
- Заявку на временное повышение лимита — суперпользователь меняет личный
  лимит в таблице пользователей.
