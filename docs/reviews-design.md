# Отзывы читателей о книгах — план (не реализовано)

Согласовано с пользователем 2026-10-26.

## Что видит пользователь

- **Карточка книги** — раздел «Отзывы»: средняя оценка читателей и число
  отзывов, список отзывов, форма «Ваш отзыв».
- **Отзыв** — оценка 1–5 звёзд и необязательный текст (до ~3000 символов,
  простой текст с переносами строк). **Можно поставить только оценку, без
  текста** (решение пользователя). У пользователя на книгу один отзыв:
  можно изменить или удалить.
- **Средняя оценка читателей** — рядом с внешними рейтингами (★ samlib,
  👍 author.today, ★ fantlab…): в карточке, в списках книг, в «Случайной
  книге», например «♥ 4,5 (3)». Сортировки по ней пока не нужно (решение
  пользователя).
- **Профиль → «Мои отзывы»** — свои отзывы со ссылками на книги.
- **OPDS-каталог (читалки)** — строка «Оценка читателей: ★★★★☆ 4,5 (3)» в
  описании книги (`book_services.book_description`). Отдельного поля
  рейтинга нет ни в OPDS 1.2, ни в 2.0, а описание показывают все
  читалки — так делает, например, Calibre. Тексты отзывов в OPDS не идут.

## Подпись отзыва (решение пользователя: вариант «б»)

По умолчанию отзыв подписан **«Читатель»**: по правилам проекта имена
других пользователей видит только суперпользователь. В профиле —
галочка «Подписывать мои отзывы» (по умолчанию выключена). Если она
включена, подпись — **отображаемое имя** (`UserProfile.display_name`, поле
уже есть), а не логин: логин — половина данных для входа и наружу не
показывается. Без заполненного имени галочку не включить. Себе
пользователь видит «ваш отзыв»; суперпользователь — всегда логин автора.
Это осознанное исключение из правила об именах: в CLAUDE.md
(«Безопасность учётной записи») дописать вместе с реализацией.

## Кто видит отзыв

Отзыв виден тем, кто видит книгу (`opds_catalog/visibility.py`), — и на
сайте, и средняя оценка в OPDS. Чужая книга по id — 404, отзывы к ней — тоже.
Средняя оценка — по всем не скрытым отзывам книги.

## Привязка: отзыв не должен пропасть вместе с записью книги

Запись `Book` недолговечна. Перемещение, переименование, сжатие и сборка
томов в сборник создают новую запись: так уже сейчас при автокомпиляции
пропадают записи книжной полки (`bookshelf` — CASCADE по книге). Поэтому
отзыв привязан **к пути файла в библиотеке**, как владение
(`LibraryFileOwner.rel_path`), и следует за ним по тем же событиям
`fb2parser_core/ownership_hooks.py` → `opds_catalog/ownership.py`:

- `transfer` (файл переехал) — отзывы переезжают на новый путь;
- `merge` (тома слились в сборник) — отзывы томов переходят на сборник с
  пометкой «о томе N «Название»» (решение пользователя: так нормально);
  если у пользователя отзывы на несколько томов — остаются все, каждый со
  своей пометкой;
- `release` без файла (файл удалён) — отзывы не удаляются, а прячутся;
  файл вернётся на тот же путь — вернутся и они.

Связь «отзыв → книга» при показе — по пути (`Book.path` + `filename`).
Проверить при реализации: что делает с записью книги повторное
сканирование и не нужен ли индекс для выборки по пути.

## Модерация

- **Суперпользователь** — Настройки → вкладка «Отзывы»: свежие отзывы с
  логином автора и книгой, «скрыть/вернуть» (как у новостей — без удаления).
- **Пользователь** удаляет свой отзыв по-настоящему (его текст).
- Пишут только свои пользователи (регистрации нет) — защита от спама не нужна.

## Этапы

1. Модель `Review`: путь файла, пользователь, оценка, текст, «о томе…»,
   скрыт, создан/изменён. Галочка подписи в профиле. Подключение к
   `transfer`/`merge`/`release`, тесты на переезд, сборку томов и удаление файла.
2. Карточка книги: показ, форма, изменение и удаление своего отзыва,
   средняя оценка.
3. Средняя оценка в списках книг и «Случайной книге»; «Мои отзывы» в профиле.
4. Вкладка «Отзывы» в настройках (суперпользователь).
5. Оценка в описании книги в OPDS.

Всё — один выпуск `feat:` (новый YY) с миграцией. Позже, если понадобится:
отзывы в «Новостях»/блок «Новые отзывы», оценка в Telegram-боте,
сортировка по оценке читателей.

## Обязательно по правилам проекта (CLAUDE.md)

- Текст отзыва и имя — в HTML только экранированными (и в описании OPDS).
- Новые адреса:
  - тест изоляции «отзыв к чужой книге не виден и не пишется» в
    `tests/integration/access/`;
  - строка в `test_url_coverage.py`;
  - во время ремонта закрыты (в `maintenance.ALLOWED` не добавлять).
- Весь новый текст — `{% trans %}` и перевод в `.po` (ru).
- Права — по `is_superuser`; роль в текстах — «суперпользователь».
- Изменение static — поднять `CACHE_VERSION` в `sw.js`.

## Замечено при проектировании (не относится к отзывам)

`book_services.book_description` (описание книги в OPDS) вставляет
название, авторов, жанры и серии из файла книги в HTML без экранирования.
Читалка, показывающая описание как HTML, отрисует разметку из метаданных
книги. Исправить отдельно (`fix:`/`security:`).
