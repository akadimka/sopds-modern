# Журнал действий пользователей

План согласован с пользователем 2026-11-02 (решения — в конце). **Все четыре
шага сделаны** (2026-11-03…06, «Сделано» в конце). Общий журнал видит только
суперпользователь (CLAUDE.md: имена других пользователей — только ему);
каждый пользователь видит только свои последние входы (раздел «Свои входы —
в профиле»).

## Зачем

1. **Безопасность.** Кто и откуда входил, неудачные входы и блокировки,
   смена пароля, новые устройства, выданные пароли для читалок, привязка
   Telegram — чтобы заметить чужой вход и понять, что произошло.
2. **Разбор жалоб.** «У меня пропала книга», «не могу войти», «кто изменил
   настройку» — ответ по журналу, а не по логам gunicorn.
3. **Картина использования.** Кто что читает и скачивает, какие каналы
   живы (сайт, приложение, OPDS, Telegram) — без отдельной статистики.
4. **Изменения на сервере.** Что поменял суперпользователь: пользователи и
   роли, настройки, новости, режим «На реконструкции», операции с
   библиотекой.

## Что записывать

Одна запись — одно действие человека (или системы от его имени), понятное
без технических подробностей. События сгруппированы по категориям — по ним
же фильтр в интерфейсе.

### Вход и безопасность (всё, без исключений)

| Событие | Подробности |
|---|---|
| вход на сайт / в приложение | устройство, IP; вход по коду из Telegram или с приложением второго фактора |
| неудачный вход | введённое имя (даже несуществующее), IP; **пароль — никогда** |
| блокировка после неудачных попыток / снятие блокировки | django-axes; кто снял |
| неверный код второго фактора, блокировка по кодам | `login_codes.note_failure` / `account_locked` |
| выход | кнопкой «Выход» / по истечении — не пишем |
| новое устройство, удаление устройства, отказ по лимиту устройств | `devices.register` / `sign_out` |
| смена своего пароля, сброс пароля суперпользователем, обязательная смена | без самих паролей |
| пароль для читалок: создан, отозван; первый вход читалки с ним | название пароля, не сам пароль |
| Telegram: привязан, отвязан | имя в Telegram |
| приложение второго фактора: подключено, отключено, сброшено (`totp_reset`) | |

### Чтение и скачивание

| Событие | Как не утонуть в записях |
|---|---|
| открыл книгу в читалке (сайт, приложение) | **одна запись на книгу в день** у пользователя; сохранение места чтения (каждые 1,5 с) не пишем |
| дочитал книгу (≥ 98 %) | один раз — момент `bookshelf.finished` |
| сохранил книгу для чтения без сети / убрал | из читалки — отдельный запрос |
| скачал файл: сайт, OPDS, Telegram | каждое скачивание; формат (fb2, epub, mobi…) |

Что **не пишем**: обложки и миниатюры, листание каталогов OPDS и страниц
сайта, подсказки поиска, фоновые опросы. **Поисковые запросы — не пишем**
(решение пользователя): это самое личное и самое шумное.

### Учётные записи и права (действия суперпользователя)

Создание пользователя, смена роли, блокировка и разблокировка, удаление,
личные лимиты (устройства), открытие библиотеки другому пользователю и
отзыв, «открыта всем». У записи два участника: **кто сделал** (суперпользователь)
и **над кем** (пользователь); было → стало для изменённых полей.

### Сайт и библиотека (действия суперпользователя)

- Настройки: какая вкладка, какие поля изменились (было → стало; пароли,
  токены и ключи — только «изменено», без значений).
- Новости: публикация, правка, скрыть/показать, закрепить, отправка в
  Telegram.
- «На реконструкции»: включён/выключен, с сайта или командой
  `manage.py maintenance`.
- fb2parser и операции с библиотекой: синхронизация, компиляция, сжатие,
  чистка (`library_cleanup --apply`), объединение псевдонима, правка
  жанров — **одна запись на операцию** с итогами (сколько книг перенесено,
  собрано, удалено, ошибок), не на каждый файл. Пофайловая история
  владения уже есть в `LibraryOwnershipLog` — журнал на неё ссылается, а
  не дублирует.
- Ручной запуск сканирования, перезапуск сервера.

### Система

Автосинхронизация и плановое сканирование — итог (добавлено, удалено,
ошибок); сбой загрузки рейтингов. Участник — «система».

## Как устроено

### Хранение

Новая модель `ActivityEvent` (приложение `sopds_web_backend`):

| Поле | Зачем |
|---|---|
| `at` | время (индекс) |
| `user` → User, `SET_NULL` + `username` (копия) | чьё действие; копия имени — запись не теряет смысл после удаления пользователя |
| `actor` → User, `SET_NULL` + `actor_name` | кто сделал, если не сам пользователь (суперпользователь, система) |
| `category`, `action` | коды из одного списка (`activity.ACTIONS`): категория для фильтра, действие для текста |
| `channel` | `web`, `pwa`, `opds`, `telegram`, `fb2parser`, `system`, `cli` |
| `ok` | успех / отказ — подсветка в интерфейсе, фильтр «только отказы» |
| `object_type`, `object_id`, `object_label` | книга, пользователь, новость…; подпись — копия на момент события («Автор - Название») |
| `device` → UserDevice, `SET_NULL` | с какого устройства |
| `ip` | **только** у событий категории «Вход и безопасность» (решение пользователя); у остальных — пусто |
| `details` | JSON: было → стало, формат, итоги операции; **никогда** не пароли, коды, токены, cookie |

Индексы: `(at)`, `(user, at)`, `(category, at)`. База — та же SQLite
(WAL). Нагрузка: входы и скачивания — единицы-сотни в день, чтение
сжато до одной записи на книгу в день — запись в базу на такие события
незаметна.

### Запись — одна точка

`sopds_web_backend/activity.py`: `record(request_or_none, action, *,
user=None, obj=None, ok=True, **details)`. Сама определяет канал (по адресу
запроса; «приложение» сервер по запросу не отличит от сайта — страница в
установленном приложении (`display-mode: standalone`) ставит cookie
`sopds_app=1`, её и смотрим), устройство
и IP (`devices._client_ip`, с учётом `SOPDS_TRUSTED_PROXIES`). **Сбой
записи не ломает действие**: исключение — в лог, запрос продолжается (как
`ownership._safe`).

Откуда вызывается:
- сигналы Django `user_logged_in`, `user_login_failed`; сигналы axes
  (`user_locked_out`);
- явные вызовы в местах действий: `views.py` (настройки, пользователи,
  новости, пароли, Telegram), `devices.py`, `login_codes.py`,
  `opds_passwords.py`, `dl.py` (скачивание, читалка, `SaveProgress` при
  `finished`), бот Telegram (скачивание), `maintenance.py`, задачи
  fb2parser (по завершении), команды `library_cleanup`, `totp_reset`;
- новый адрес = новое событие: правило в CLAUDE.md рядом с «Видимостью книг»
  (как тест изоляции для новых адресов).

### Хранение во времени

Сроки — **настройки суперпользователя** (решение пользователя), на вкладке
«Журнал» сверху, блок «Хранение журнала»:

| Настройка (`config.json`, `sopds`) | Что | По умолчанию |
|---|---|---|
| `activity_keep_security_days` | «Вход и безопасность», «Учётные записи и права», «Сайт и библиотека», «Система» | 365 |
| `activity_keep_reading_days` | «Чтение и скачивание» | 90 |

**0 — хранить бессрочно.** Хранятся там же, где другие настройки сайта
(`SettingsManager(_site_config_path())`, как `devices_per_user`); поле —
целое ≥ 0, подпись поясняет «0 — бессрочно». Чистка — раз в сутки в
плановом сканере (`sopds_scanner`), плюс `manage.py activity_cleanup`
(с `--dry-run`); категория со сроком 0 не чистится. Удаление пользователя
записи не стирает (имя сохранено копией) — это след действий над ним.

## Как показывать

### Где

1. **Настройки → новая вкладка «Журнал»** (`?tab=journal`, рядом с
   «Пользователи»; только суперпользователь, как все настройки). Основной
   экран.
2. **Пользователи → у каждого пользователя ссылка «Журнал»** — та же
   вкладка с фильтром по нему.
3. **Карточка книги** (только суперпользователю): небольшой блок «Кто
   читал и скачивал» — последние 10 событий по книге и ссылка «весь
   журнал книги».
4. **Шапка** (только суперпользователю): рядом с «Сейчас на сайте» —
   красная метка, если за сутки были блокировки или неудачные входы с
   новых адресов; ведёт в журнал с фильтром «Безопасность, только отказы».

### Свои входы — в профиле (каждому пользователю)

Решение пользователя: каждый видит **только свою** историю входов — чтобы
заметить чужой вход. В профиле (страница настроек пользователя) блок
**«Последние входы в вашу учётную запись»**: последние 20 событий из
категории «Вход и безопасность», где `user` — он сам: успешные входы
(дата, устройство, IP, канал), неудачные попытки с его именем (IP),
блокировки, новые устройства, смена пароля, пароли для читалок, привязка
Telegram. Ссылка «Это был не я» — на смену пароля и список устройств (там
можно удалить устройство). Чужих событий и имён других пользователей в
блоке нет — тест изоляции: у Анны не видно входов Бориса. Для
суперпользователя этот блок — тоже только его собственные входы; общий
журнал — на вкладке «Журнал».

Предупреждения о том, что действия записываются, пользователям **не
показываем** (решение пользователя).

### Экран «Журнал»

```
┌─ За сегодня ───────────────────────────────────────────────────────────┐
│ Входов 12 · Неудачных 3 (⚠ 1 блокировка) · Открыто книг 41 · Скачано 9 │

[Период: Сегодня ▾] [Пользователь: все ▾] [Категория: все ▾] [Канал: все ▾]

── 2 ноября, понедельник ─────────────────────────────────────────────────

22:03  ✗ (нет)   🌐 сайт        🔒 Неудачный вход  имя «admn», 85.12.…  ▸
21:57  admin     🌐 сайт        ⚙ Изменил настройки  Расписание: 05:00 → 04:30
21:40  boris     📚 OPDS        ⤓ Скачал (epub)   Пехов Алексей - Киндрэт
21:12  система   ⚙ fb2parser    🔄 Синхронизация   +23 книги, 0 ошибок
```

- Строка — время, кто, канал (иконка + подпись), действие (иконка
  категории + понятный текст), объект — ссылка (карточка книги, страница
  пользователя, новость). Отказы — красным, блокировки — с ⚠.
- «▸» раскрывает подробности: устройство, IP, было → стало, итоги операции.
- Группы по дням с заголовком даты; время — в часовом поясе сайта
  (`TIME_ZONE`).
- Фильтры — htmx, без перезагрузки, адрес страницы содержит фильтр (можно
  дать ссылку). Постранично по 50, «показать ещё».
- Телефон: вместо таблицы — карточки (время и действие сверху, кто и
  объект ниже), фильтры — в раскрывающейся панели.
- Все тексты — `{% trans %}` + перевод (CLAUDE.md); названия книг и имена —
  только экранированными.
- **CSV** — выгрузка выбранного (для разбора вне сайта).

Сводка «За сегодня» — те же фильтры одним кликом: «Неудачных 3» открывает
журнал с фильтром «Безопасность, только отказы».

## Доступ и безопасность самого журнала

- Все адреса журнала — `sopds_admin` (по `is_superuser`), тесты: у
  пользователя — отказ, в блоке книги в карточке — ничего; строки в
  `test_url_coverage.py` (`NO_CATALOG_DATA` нельзя — в журнале есть книги:
  тест, что журнал виден только суперпользователю).
- В журнал не попадают пароли, коды, токены, содержимое cookie, тексты
  поиска. Проверка — тест, который прогоняет все действия с известным
  паролем и ищет его в `details`.
- «На реконструкции»: журнал — часть настроек, суперпользователю открыт.
- Журнал только дополняется: правки и удаления записей из интерфейса нет
  (чистка по сроку — только автоматическая).

## Порядок работ

1. **Основа и безопасность.** Модель и миграция, `activity.record`, все
   события «Вход и безопасность», вкладка «Журнал» с фильтрами, сводкой и
   подробностями, настройки сроков хранения и чистка по ним, блок «Последние
   входы» в профиле, правило в CLAUDE.md, тесты (доступ к журналу только у
   суперпользователя, в профиле — только свои входы, нет паролей в журнале,
   каждое событие пишется, срок 0 — не чистится). Отдельный выпуск.
2. **Чтение и скачивание** (сайт, приложение, OPDS, Telegram) со сжатием
   «одна запись на книгу в день», блок в карточке книги.
3. **Действия суперпользователя**: пользователи и права, настройки (было →
   стало), новости, «На реконструкции»; ссылка «Журнал» у пользователя.
4. **fb2parser и система**: итоги операций, ссылка на `LibraryOwnershipLog`,
   метка в шапке, выгрузка CSV.

## Сделано

**Шаг 1 — основа и безопасность (2026-11-03).**
- Модель `ActivityEvent` (миграция `0013_activity_event`), запись —
  `sopds_web_backend/activity.py` (`record`, список действий `ACTIONS`,
  фильтры, сводка, чистка). Подробности чистятся от ключей со словами
  password/code/token/secret/cookie/session/key.
- События: вход (сайт, приложение, OPDS — способ: пароль, приложение-
  аутентификатор, код из Telegram, пароль для читалок), неудачный вход
  (введённое имя, причина: неверный пароль, нет такого пользователя,
  учётная запись отключена, читалке основной пароль не годится), блокировка
  django-axes (сигнал `user_locked_out`; попытки во время блокировки — только
  она, без «неудачного входа»), вход отклонён (лимит устройств, коды,
  код не доставлен), выход кнопкой, неверный код второго фактора и
  блокировка по кодам (`login_codes.note_failure`), новое устройство,
  удаление устройства (собой и суперпользователем), смена пароля (своя,
  обязательная, заданная суперпользователем), пароль для читалок (создан,
  отозван — в том числе сменой пароля, первый вход читалки), Telegram
  (привязан ботом, отвязан собой и суперпользователем), приложение-
  аутентификатор (подключено, отключено, `totp_reset`).
- **Снятие блокировки не пишется:** на сайте его нет — блокировка axes
  истекает сама через час (`AXES_COOLOFF_TIME`) или снимается на сервере
  `manage.py axes_reset`.
- «Приложение» — cookie `sopds_app=1`, её ставит страница в установленном
  приложении (`display-mode: standalone`) и снимает обычная вкладка.
- Вкладка «Журнал» (`/web/settings/journal/`): сводка «Сегодня» (входы,
  неудачные и блокировки, активные пользователи — ссылки на фильтр),
  фильтры (период — по умолчанию 7 дней, пользователь, категория, канал,
  только отказы; htmx, адрес с фильтром), группы по дням, «▸» —
  подробности, «Показать ещё» по 50; на телефоне — карточки. Сроки
  хранения — там же (`activity_keep_security_days`/`_reading_days` в
  `config.json`, 365/90, 0 — бессрочно); чистка — плановый сканер в 04:17 и
  `manage.py activity_cleanup [--dry-run]`.
- Профиль: «Последние входы в вашу учётную запись» — 20 своих событий
  безопасности, ссылки на смену пароля и устройства.
- Тесты — `tests/integration/sopds_web_backend/test_activity_log.py`
  (события, нет паролей в журнале, только суперпользователь, только свои
  входы в профиле, сбой записи не ломает вход, сроки и чистка).

**Шаг 2 — чтение и скачивание (2026-11-03).**
- События: открыл книгу в читалке (сайт, приложение, OPDS — `render_book_html`;
  **одна запись на книгу в день**, `record(..., once_per_day=True)`),
  дочитал (≥ 98 % — момент `bookshelf.finished`, один раз), сохранил для
  чтения без сети / убрал (кнопка «⤓» читалки сообщает тем же адресом, что
  место чтения: `opds:save_progress` с полем `offline` — отдельного адреса
  нет, место чтения при этом не меняется), скачал — каждое скачивание с
  форматом (`fb2`, `fb2.zip`, `epub`…): `opds:download`, `opds:convert`,
  бот Telegram (`telegram_library.deliver`, и по file_id).
- Канал: адреса `/opds/` из сессии сайта (кнопки «скачать» в карточке) —
  «сайт»/«приложение», из сессии читалки — OPDS.
- Без входа (SOPDS_AUTH выключен) чтение не пишется — чьё оно, неизвестно.
- Журнал: фильтр по книге (`?book=<id>`), подпись книги в строке — ссылка на
  её журнал; в сводке «Сегодня» — открыто книг и скачано.
- Карточка книги: «Кто читал и скачивал» — последние 10 событий и «Весь
  журнал книги», только суперпользователю.
- Тесты — тот же `test_activity_log.py` (раз в день, дочитал один раз,
  «⤓» не трогает место чтения, форматы и каналы скачивания, без входа — не
  пишется, карточка — только суперпользователю), Telegram —
  `test_telegram_download.py`.

**Шаг 3 — действия суперпользователя (2026-11-06).** У записи два
участника: кто сделал (`actor`) и над кем (`user`).
- Учётные записи: создан пользователь (роль), смена роли (было → стало),
  личный лимит устройств (было → стало, «по умолчанию»), удалён
  пользователь (имя остаётся копией), удаление своей учётной записи из
  профиля.
- `/admin/`: любое изменение там — по его истории (`LogEntry`, сигнал в
  `signals.py`): пользователь — «Изменение пользователя в /admin/» (так
  пишутся блокировка и разблокировка — в интерфейсе сайта их нет), прочее —
  «Изменение в /admin/», с текстом «что изменено» от Django.
- Настройки: общая форма (вкладки «Общие», «Сканер», «Расписание»,
  «Telegram»), настройки на вкладке «Пользователи», сроки журнала — одна
  запись на сохранение: вкладка, «поле: было → стало» по действующим
  значениям (с умолчаниями); токены, пароли, ключи, прокси — только имя
  поля («изменены, значения не показываются», `activity.settings_changes`).
- «На реконструкции»: включён/выключен — отдельное событие, с сайта и
  командой `manage.py maintenance on|off` (канал «консоль сервера»).
- Новости: опубликована, изменена, скрыта / снова показана, закреплена /
  откреплена, отправлена в Telegram (ошибка отправки — отказ с текстом).
- Вкладка «Пользователи»: у каждого — ссылка «Журнал» (фильтр по нему).
- **Не пишется — интерфейса нет:** «открыть библиотеку другому
  пользователю» (`LibraryShare`) и «открыта всем» (`library_public`) на
  сайте и в /admin/ не меняются; запись — вместе с интерфейсом.
- Тесты — `test_activity_log.py` (секреты настроек, сроки и «На
  реконструкции», пользователи — кто и над кем, новости, /admin/, ссылка
  «Журнал»).

**Шаг 4 — fb2parser и система (2026-11-06).**
- Операции fb2parser — одна запись на операцию, кто запустил — `started_by`
  в состоянии задачи (`JobState`), итоги — «Итоги: ключ: число» (только
  ненулевые, `activity.totals`), ошибка — отказ с текстом: синхронизация
  (в том числе в отдельном процессе), компиляция, сжатие, назначение жанра
  папкам. Сразу (запрос): удаление файлов («Великомученницы», битые,
  дубликаты — сколько удалено), правка списка жанров (каждый `genres_*`,
  если удалась: операция и значения), объединение написаний автора,
  перезапуск сервера, ручной запуск сканирования.
- Команды (канал «консоль сервера»): `library_cleanup --apply` (часть и
  итог), `library_rename_author --apply`, `maintenance`.
- Система (кто — «система»): итог сканирования библиотеки (по расписанию и
  ручного — с тем, кто запустил: добавлено, удалено, битых), автосинхронизация
  — только прогон, который что-то перенёс, удалил или упал (пустые идут после
  каждого скана), «сайт рейтингов не отвечает» (`pause_for_outage`, раз в сутки
  на источник), сбой фонового потока рейтингов.
- История владения по файлам (`LibraryOwnershipLog`) не дублируется: на
  сайте её показа нет, расхождения — `manage.py library_owners_check`;
  журнал хранит итог операции.
- Шапка суперпользователя: «⚠ Безопасность: N» — за сегодня блокировки и
  неудачные входы с адресов, с которых у этого имени не было успешного входа
  (`activity.security_alerts`, кэш на минуту); ведёт в журнал с фильтром
  «Безопасность, только отказы».
- «⤓ CSV» в фильтрах журнала — выгрузка по тем же фильтрам (UTF-8 с BOM,
  до 100 000 строк, `?format=csv`).
- Подписи значений подробностей — по своему ключу (`DETAIL_TEXTS`): код
  «telegram» — и способ входа, и вкладка настроек.
- Тесты — `test_activity_log.py` (итоги операций и кто запустил, удаления,
  жанры, перезапуск, система, метка в шапке, CSV, подписи значений).
