# Серверы: перевести на HTTPS и закрыть порт 8008 — к выполнению

Найдено при аудите безопасности 2026-10-01. Отложено до доступа к
серверам; пошаговая инструкция — `DEPLOY.md`, шаг **12a**.

## Почему

`sopds.settings.gunicorn` слушает `0.0.0.0:8008`, а `DEPLOY.md`
допускает открывать сайт напрямую по `http://<IP>:8008/`. Если сервер
доступен из интернета, по сети открытым текстом идут:

- пароль при входе на сайт и cookie сессии (`sessionid`) — перехват
  cookie = вход под этим пользователем;
- логин/пароль OPDS-клиентов (Basic-auth в каждом запросе читалки);
- CSRF-токен.

Кроме того, открытый 8008 позволяет обойти Apache, если он настроен.

Менять `bind` в `gunicorn.py` для всех нельзя: серверы, где сайт
открывают именно по `:8008`, перестанут открываться. Решается на
каждом сервере отдельно — HTTPS на Apache и `--bind 127.0.0.1:8008` в
systemd-юните.

## Чек-лист на сервере

Перед началом — консольный доступ (KVM/физический) на случай потери
сети после firewall.

- [ ] Обновить код (история `master` переписана 2026-10-02): `git status`
      → `git stash` → `git fetch origin && git reset --hard origin/master`
      → `git stash pop`, затем шаги раздела «Обновление» в `DEPLOY.md`
- [ ] Выяснить, как сейчас открывают сайт пользователи и OPDS-читалки
      (`:8008` напрямую или через Apache) — после переключения им
      понадобится новый адрес `https://…`
- [ ] Сертификат: Let's Encrypt (есть домен) или самоподписанный (только IP)
- [ ] Apache: `*:443` с проксированием на `127.0.0.1:8008` и
      `RequestHeader set X-Forwarded-Proto "https"`, `*:80` — редирект
- [ ] systemd: `--bind 127.0.0.1:8008` в `ExecStart`, `ss -ltnp | grep 8008`
      показывает только `127.0.0.1`
- [ ] `.env`: `SOPDS_USE_HTTPS=True`, `SOPDS_TRUST_X_FORWARDED_PROTO=True`
      (только после предыдущего пункта), `ALLOWED_HOSTS`
- [ ] Firewall: сначала SSH-порт, затем 80/443, `deny 8008`; на роутере
      убрать проброс 8008
- [ ] Проверка с другого компьютера: `:8008` не соединяется, `http://` → 301,
      `https://…/web/login/` → 200, cookie с флагом Secure, вход и
      сохранение настроек работают (нет ошибки CSRF)
- [ ] Обновить адрес каталога в OPDS-читалках на `https://<…>/opds/`
- [ ] Отметить результат здесь и в `docs/deploy-sopds-modern-2-status.md`
