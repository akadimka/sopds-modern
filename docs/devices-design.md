# Ограничение устройств учётной записи

Статус: решения согласованы с владельцем репозитория 2026-10-21; этап 1 сделан.
Задача: одна учётная запись не должна использоваться множеством людей —
суперпользователь задаёт каждому пользователю лимит устройств, пользователь
сам управляет списком своих устройств.

## Решения (согласованы)

1. **Устройство — это браузер** (сайт `/web/`, PWA, fb2parser). Читалки OPDS
   работают по общему паролю пользователя (основному или паролю для читалок —
   как сейчас) и **не считаются** устройствами: идентифицировать их нечем
   (cookie они обычно не хранят), а таких подключений мало. Telegram — тоже не
   устройство (у пользователя и так только один привязанный аккаунт).
2. **Лимит** — число устройств на пользователя: значение по умолчанию в
   настройках (раздел квот, 0 = без ограничений), личное значение — у
   пользователя на странице пользователей (пусто = по умолчанию, 0 = без
   ограничений). **На суперпользователя лимит не действует**, но список
   устройств у него есть — управлять ими (потерял телефон) он может так же.
3. **Лимит исчерпан** — вход с нового устройства отклоняется с сообщением
   «Достигнут лимит подключённых устройств (N)…»: удалить ненужное устройство
   в настройках на одном из своих устройств или обратиться к суперпользователю.
   Вытеснения нет.
4. **Автоудаления нет.** Пользователь сам управляет своими устройствами:
   видит все, даёт каждому описание («телефон», «рабочий компьютер»), удаляет
   любое, освобождая место. Суперпользователь может сделать то же с
   устройствами любого пользователя.

## Как распознаётся устройство

Браузер не отдаёт «железный» идентификатор, отпечаток браузера ненадёжен и
похож на слежку. Поэтому при первом входе браузер получает **метку
устройства** — cookie `sopds_device`: случайные 32 байта, `HttpOnly`,
`Secure` (на HTTPS), `SameSite=Lax`, срок 2 года, продлевается при
использовании. В базе — только SHA-256 метки.

- Метка живёт, пока пользователь не очистит cookie; другой браузер, режим
  инкогнито, на iOS — установленное PWA отдельно от Safari (у него свои
  cookie) — новое устройство. Установленное PWA на Android делит cookie с
  Chrome — то же устройство.
- Одна метка в одном браузере может принадлежать нескольким учётным записям
  (общий компьютер) — устройство — это пара (пользователь, метка).
- Перенести метку на другое устройство можно только сознательно (копированием
  cookie) — защита от «дал пароль другу», не от взлома.

## Модель

`UserDevice` (`sopds_web_backend`): `user`, `token_hash` (SHA-256, индекс),
`name` (описание от пользователя), `user_agent`, `label` (авто: «Chrome,
Windows», «Safari, iPhone» — по User-Agent, без новых зависимостей),
`created_at`, `last_seen`, `last_ip`; уникальность (`user`, `token_hash`).

`UserProfile.max_devices` — `NULL` = по умолчанию из настроек, `0` = без
ограничений. Настройка `devices_per_user` (config.json, раздел квот, 0).

## Поведение

- **Вход (страница входа).** После проверки пароля и до кода второго
  фактора: устройство известно (метка этого браузера уже у пользователя) или
  лимит не исчерпан — вход продолжается; иначе — отказ с сообщением, код
  второго фактора не отправляется. Устройство регистрируется при
  завершённом входе (после кода).
- **Каждый запрос** (middleware): сессия сайта (не OPDS-сессия
  `opds_only`) привязана к устройству. Устройство удалено — выход с
  сообщением «Это устройство удалено из ваших устройств». Сессии, открытые
  до включения функции, привязываются при первом запросе; если лимит уже
  исчерпан — выход с тем же сообщением, что и при входе.
- **Одновременные запросы.** Браузер шлёт несколько запросов сразу
  (страница + htmx); у сессии без устройства каждый завёл бы своё (так и
  было: встроенный браузер VS Code — 4 устройства за миллисекунду). Метка
  такой сессии вычисляется из ключа сессии (HMAC с SECRET_KEY) — устройство
  одно (уникальность в базе). Метка после обычного входа — случайная:
  перенесённая в другой браузер сессия — новое устройство.
- **«Мои устройства»** — в настройках пользователя (страница профиля):
  таблица (описание — редактируется, авто-имя, первый вход, последняя
  активность, последний IP, отметка «это устройство»), кнопка «Удалить»
  (с подтверждением; удаление текущего — выход). Сверху — «Устройств: k из N».
- **Суперпользователь** на странице пользователей: колонка «Устройства k / N»,
  поле лимита, ссылка на список устройств пользователя с удалением.

## Этапы

1. Модель, миграция, настройка и поле лимита; распознавание и регистрация
   устройства при входе, отказ при исчерпанном лимите; middleware (привязка
   сессии, выход при удалённом устройстве).
2. «Мои устройства» в настройках пользователя (описание, удаление).
3. Лимит и устройства пользователя на странице пользователей; значение по
   умолчанию в настройках сайта.
Каждый этап — тесты (вход с нового устройства при исчерпанном лимите —
отказ; известное устройство — вход; удаление — выход; OPDS не считается;
суперпользователь — без лимита) и переводы (`{% trans %}` + ru `.po`).
