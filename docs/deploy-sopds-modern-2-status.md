# Второй сервер (sopds-modern-2) — статус

> Адрес, порты, имена пользователей и SSH-ключ здесь заменены плейсхолдерами —
> репозиторий публичный. Реальные значения хранятся локально, вне репозитория.

Второй, независимый экземпляр sopds-modern (своя библиотека, не связана с
основным сервером `sopds-modern`/turnkey). Развёрнут по `DEPLOY.md` с
поправками под Debian 13 (trixie) вместо Debian 11/TurnKey 17.

**Сервер:** `<SERVER_IP>` за роутером MikroTik (RouterOS), внутренний адрес
`<INTERNAL_IP>`. SSH: внешний порт `<SSH_PORT>` проброшен на 22, пользователь
`<ADMIN_USER>` (sudo с паролем). SSH-алиас `sopds-modern-2` в `~/.ssh/config`.

Секреты (SSH-пароли, пароль суперпользователя Django) в этот файл
**намеренно не записаны**. Пароль суперпользователя стоит сменить после
первого входа.

## Доступ: только с российских адресов

Сервер (или сеть провайдера) принимает подключения только с российских
IP. Рабочий ПК выходит в интернет через зарубежный VPN — с него подключение
просто зависает по таймауту, как будто сервер выключен; с телефона
(российский IP) всё работает.

Поэтому в `~/.ssh/config` для `sopds-modern-2` указан
`ProxyJump sopds-modern` — соединение идёт через основной сервер, который
выходит в интернет через российского провайдера. Ключ остаётся на ПК.

> 2026-09-23 это было ошибочно принято за блокировку после `ufw enable`.
> На деле сервер всё это время работал (18 дней без перезагрузки на
> 2026-10-07), ufw настроен верно.

## Что развёрнуто (2026-10-07)

- Код на актуальном `master` (клон обновлён после переписывания истории
  2026-10-02), Django 5.2.17, миграции применены.
- `.env`: SQLite, `ALLOWED_HOSTS=<SERVER_IP>,localhost,127.0.0.1`,
  `SOPDS_USE_HTTPS=True`, `SOPDS_TRUST_X_FORWARDED_PROTO=True`.
- `config.json` (машинный, вне git): библиотека `/srv/sopds-books`
  (SOPDS и FB2Parser), авторизация на весь каталог, Calibre
  (`/usr/bin/ebook-convert`) для EPUB/MOBI/AZW3, включены все четыре
  источника рейтингов.
- Сервисы (enabled, active), юниты — как на основном сервере:
  `sopds-modern` (gunicorn, `--bind 127.0.0.1:8008`), `sopds-scan`,
  `sopds-watch`, `sopds-samlib`, `sopds-authortoday`, `sopds-fantlab`,
  `sopds-litmarket`, плюс `apache2` и `memcached`.
- `/etc/sudoers.d/sopds-modern-restart` — `www-data` может только
  `systemctl restart sopds-modern` (кнопка «Перезапуск» в веб-интерфейсе).
- Apache: самоподписанный сертификат (`/etc/ssl/sopds-modern/`, 10 лет),
  443 → `127.0.0.1:8008`, 80 → редирект на HTTPS.
- ufw: разрешены 22, `<SSH_PORT>`, 80, 443; 8008 снаружи закрыт.

Изнутри проверено: HTTPS через Apache, `/web/login/`, `/admin/login/`,
OPDS отвечает 401 без авторизации.

## Что нужно от админов

1. **Проброс `80/tcp` и `443/tcp`** на `<INTERNAL_IP>` (как уже сделано
   для SSH). Сейчас внешний порт 80 открывает страницу входа в веб-интерфейс
   самого роутера (RouterOS), а 443 никуда не ведёт — снаружи сайт не
   открывается.
2. **Убрать веб-интерфейс роутера из интернета** (или перевести на
   другой порт с ограничением по адресам).

## Осталось

- После проброса портов — проверка в браузере: `https://<SERVER_IP>/`
  (ожидаемо предупреждение о самоподписанном сертификате), `/fb2parser/`,
  `/admin/`.
- Залить книги в `/srv/sopds-books` — `sopds-watch` подхватит их сам.
- Сменить пароль суперпользователя.
- (Опционально) автосинхронизация папки загрузок и Telegram — `DEPLOY.md`,
  шаг 19a.
