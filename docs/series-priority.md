# Приоритет источников серии/номера тома в regen_csv

Единый источник правды для правил, которые иначе выводятся заново
каждый раз при разборе нового краевого случая в `fb2parser_core`. Если
код и этот документ расходятся — документ обновляется, а не
переоткрывается заново в разговоре.

## Общий принцип

**Папка > имя файла > метаданные.** Как только значение получено из
более авторитетного источника, пайплайн **не должен** пытаться получить
его снова из менее авторитетного — ни "подтверждая", ни "расширяя".

## Иерархия по убыванию авторитетности

1. **Плоская папка-датасет** (`folder_dataset`) — все файлы напрямую в
   одной папке считаются одной серией по имени этой папки. Авторитетно и
   неизменяемо: даже если названия книг внутри намекают на другое
   деление (например, часть файлов называется "Пасть N", часть "Война
   родов N") — серия остаётся ОДНА, по имени папки.

2. **Вложенная подпапка = свой датасет для подсерии**
   (`folder_hierarchy`/`subfolder_hierarchy`). Если внутри папки-серии
   есть пронумерованная подпапка (`"1. Мы — были!"`), она формирует
   собственную подсерию `Родитель\Подпапка`, с собственной независимой
   последовательной нумерацией внутри. Это НЕ конфликтует с правилом 1 —
   родительская серия остаётся одна, просто с внутренней структурой дуг.

3. **`filename_prefix`** — ведущая цифра в начале имени файла
   (`"11. Название.fb2"` → 11). Строго последовательна и надёжна В
   ПРЕДЕЛАХ ОДНОЙ ПАПКИ (или подпапки-дуги) — это позиция самого файла,
   а не текст, который автор мог написать (и ошибиться) внутри
   названия. **Никогда не перезаписывается** более поздними шагами
   консенсуса (`filename_series_refix` и т.п.) — см. `pass4_consensus.py`,
   финальный шаг перечитывания номера из имени файла.

4. **Арки/дуги из текста имени файла** (`filename_named_arc`,
   `filename_word_number` и т.п.) — строятся ТОЛЬКО когда для файла НЕТ
   вообще никакого папочного сигнала о серии (ни `folder_dataset`, ни
   `folder_hierarchy`). Если папочный сигнал есть — он побеждает, дуги
   из имени файла не применяются.

5. **Метаданные** (`<sequence>` в самом FB2) — самый ненадёжный
   источник, используется только когда ничего из 1-4 не дало значения.
   Метаданные могут ПОДТВЕРДИТЬ уже полученное из файла/папки значение,
   но никогда не должны его РАСШИРЯТЬ или переопределять для СЕРИИ.
   Исключение — для АВТОРА расширение из меты допустимо (см.
   `feedback_series_meta_role` в истории проекта): роль меты разная для
   серии и для автора.

## Коллизии номеров

Если файл без `filename_prefix` (например, специальный
выпуск/альтернативное издание) получает номер из меты/консенсуса,
который СОВПАДАЕТ с уже занятым `filename_prefix`-номером другого файла
**в той же папке** — номер у не-prefix файла нужно ОЧИЩАТЬ (не
присваивать вовсе), а не оставлять дубликат. Коллизия имеет смысл только
внутри одной папки — тот же номер в другой, несвязанной папке той же
серии (например, разные сборники одного автора) коллизией не считается.

## Связанные файлы кода

- `fb2parser_core/regen_csv.py` — оркестрация 6 пасов.
- `fb2parser_core/passes/pass1_read_files.py` — сбор файлов, папочный
  консенсус (`Precache`).
- `fb2parser_core/passes/pass2_series_filename.py` — извлечение серии
  из имени файла, включая `_detect_named_arcs`.
- `fb2parser_core/passes/pass4_consensus.py` — финальная консолидация,
  включая guard против перезаписи `filename_prefix` и очистку коллизий
  номеров (см. правило "Коллизии номеров" выше).
- `fb2parser_core/fb2_compiler.py` — использует те же принципы при
  сортировке томов для компиляции (`_sort_key_for_subseries`).
