# Многопользовательская библиотека: владение, совместный доступ, загрузка

Статус: проект, согласован с владельцем репозитория 2026-10-19; реализация
по этапам (раздел «Этапы»). Документ — для тех, кто будет это реализовывать.
Пошаговый план работ — `docs/multiuser-plan.md`.

## Решения (согласованы)

1. **Библиотека «псевдоличная».** Физически библиотека одна (одно дерево
   папок `root_lib`, один каталог `sopds.db`, один сканер). Личными
   становятся права: пользователь видит только свои книги и всё, что к ним
   относится (авторы, серии, жанры, поиск, счётчики), плюс книги, которыми с
   ним поделились.
2. **Администратор = «Супер».** Отдельной роли нет: роль сайта
   «Суперпользователь» (`is_superuser`; она же управляет пользователями и
   fb2parser; «admin» — только имя учётной записи) видит всю библиотеку
   (книги всех пользователей), кто и когда что загрузил, и может изъять
   книгу — для вопросов правообладателей и юрисдикций. Владелец «по умолчанию» (файлы без
   владельца, существующая библиотека) — первый активный суперпользователь.
3. **Одинаковые книги.** Если двое загрузили одну книгу — один файл, два
   владельца. Удаление книги владельцем = отзыв его владения; файл остаётся,
   пока у него есть другие владельцы, а после ухода последнего переходит
   во владение администратора.
4. **Совместный доступ — только чтение и скачивание.** Получатель не может
   «забрать себе» чужую книгу: только скачать и затем сам загрузить её
   в свою библиотеку обычным путём (с проверкой квоты).
5. **Квоты.** Раздел «Квоты пользователей» на странице настроек; 0 = без
   ограничений (значения по умолчанию — 0). Каждому пользователю выделяется
   начальный объём, администратор может увеличить его конкретному
   пользователю.
6. **Существующая библиотека** становится библиотекой администратора и
   «открыта всем» — после миграции пользователи видят то же, что и сейчас.
7. **Чужие библиотеки — отдельными разделами** («Библиотека Ивана»), без
   общего списка «всё, что мне доступно».
8. **Загрузка книг пользователями** — через «приёмник» на ядре fb2parser,
   а не через личную копию полного инструмента (раздел «Загрузка»; требует
   отдельной детальной проработки перед этапом 3).

## Модель данных

### Владение — привязано к файлу, а не к записи каталога

Главная техническая ловушка: запись `Book` не живёт столько, сколько файл.
Сканер узнаёт книгу по `(filename, path)`; синхронизация, компиляция,
сжатие (`.fb2` → `.fb2.zip`), переименование автора (`library_rename_author`)
перемещают и переименовывают файлы — старая запись `Book` удаляется
(логически или физически), появляется новая. Владение, повешенное на
`Book.id`, при этом терялось бы.

Поэтому источник правды — владение **файлом библиотеки**:

- `LibraryFileOwner(rel_path, user, added_at, source, origin_name, origin_sha256, size)`,
  уникальность `(rel_path, user)`, индекс по `rel_path`.
  - `rel_path` — путь файла относительно `root_lib` (для книг в zip — путь zip).
  - `source`: `migration` | `upload` | `admin`.
  - `origin_sha256` — хеш файла в момент загрузки (до правки тегов
    синхронизацией): по нему ищутся дубли при следующих загрузках, потому что
    файл в библиотеке после `_patch_fb2_tags` уже другой.
- **Каждая операция, которая двигает файлы, обязана переносить владение**
  (`rel_path` старый → новый) в той же транзакции, что и запись в
  `.library_cache.db`: синхронизация, сжатие, переименование автора,
  удаление дублей, компиляция. Это — основной объём работы этапа 1 вне веб-части.
- `book_owner(book, user)` — производная связь для быстрых запросов
  каталога; заполняет сканер при добавлении/обновлении `Book` по
  `LibraryFileOwner`, поддерживают действия отзыва. Команда
  `manage.py library_owners_check` сверяет обе таблицы и чинит расхождения.

**Компиляция:** компилятор не объединяет файлы с разным набором владельцев
(иначе книга пользователя Б стала бы видна пользователю А внутри сборника).
Группа компиляции = книги одной серии **с одинаковым множеством владельцев**;
владельцы сборника = это множество. Компиляция остаётся инструментом
администратора.

**Последний владелец ушёл** — файл не удаляется, а переходит во владение
администратора (`source = admin`); администратор сам решает, удалять ли его.

### Совместный доступ

- `LibraryShare(owner, grantee, created_at)`, уникальность `(owner, grantee)`;
  делится вся коллекция владельца, только чтение и скачивание; доступ
  отзывается в любой момент; не транзитивен (получатель не может переслать).
- `UserProfile.library_public` (bool) — «открыта всем пользователям»;
  у администратора после миграции `True`.
- Позже, если понадобится: доступ к отдельной полке.

### Квоты

- В `config.json` (через `sopds_config`, раздел «Квоты пользователей» на
  `/web/settings/`), все по умолчанию `0` = без ограничений:
  - `quota_library_mb` — объём библиотеки пользователя по умолчанию;
  - `quota_books` — число книг по умолчанию;
  - `upload_max_file_mb` — размер одного загружаемого файла.
- `UserProfile.quota_library_mb`, `UserProfile.quota_books` — личные лимиты:
  `NULL` = значение по умолчанию из настроек, `0` = без ограничений.
- Объём пользователя = сумма размеров файлов, которыми он владеет; общий
  файл засчитывается **каждому** владельцу целиком (предсказуемо для
  пользователя; экономия от общих файлов — у сервера).
- Суперпользователь квотами не ограничен.

## Правило видимости

`Book.objects.visible_to(user)` (собственный `QuerySet`, менеджер по
умолчанию не меняется — у него нет доступа к пользователю):

- суперпользователь — все книги с `avail > 0`;
- пользователь — книги с `avail > 0`, у которых есть владелец из множества
  `{сам пользователь} ∪ {владельцы, поделившиеся с ним} ∪ {владельцы с library_public}`;
- аноним (только при выключенной авторизации `SOPDS_AUTH`) — книги владельцев
  с `library_public`.

Производные сущности — через `Exists(видимые книги)`: авторы, серии, жанры,
папки каталога, буквенные меню и все `Count("book")` считаются только по
видимым книгам; сущность без видимых книг не показывается (иначе видны
имена авторов/серий чужих книг).

Книга по id, которую пользователь не видит, — **404, а не 403** (чтобы
перебором id нельзя было узнать, что книга существует).

## Где нужно применить фильтр (инвентаризация на 2026-10-19)

Сейчас ни одно место, отдающее данные каталога, не проверяет пользователя
(только «вошёл ли»). Пути — относительно `src/`.

### Книга или файл по id — высший риск
| Место | Адрес |
|---|---|
| `opds_catalog/dl.py` `Download` | `/opds/download/<id>/<zip>/` — файл |
| `dl.py` `Cover`, `Thumbnail` | `/opds/cover/<id>/`, `/opds/thumb/<id>/` |
| `dl.py` `ViewHtml` | `/opds/view/<id>/` — полный текст |
| `dl.py` `ConvertFB2` | `/opds/convert/<id>/<fmt>/` — конвертированный файл |
| `dl.py` `SaveProgress` | `/opds/progress/<id>/` — создаёт запись полки для любого id |
| `sopds_web_backend/views.py` `book_card` | `/web/book/card/<id>/` |
| `SearchBooksView` типы `d`, `i`; `book_services.find_book_doubles` | поиск дублей / книга по id |
| Telegram: `telegram_search.book_screen`, `telegram_library.deliver`, deep link `b<id>`/`s<id>` | бот |

Все `dl.py` используют одинаковый `Book.objects.get(id=…)` (сейчас без
обработки `DoesNotExist` → 500): общий помощник `get_visible_book_or_404`.

### Списки и поиск
- OPDS (`opds_catalog/feeds.py`): `CatalogsFeed`, `SearchBooksFeed`,
  `BooksFeed`, `AuthorsFeed`, `SeriesFeed`, `GenresFeed`,
  `SearchAuthorsFeed`, `SearchSeriesFeed`, `MainFeed` (счётчики).
- Веб (`sopds_web_backend/views.py`): `SearchBooksView` (в т.ч. обход
  сервисов для `u`/`d`/`i`), `SearchSeriesView`, `SearchAuthorsView`,
  `CatalogsView`, `BooksView`, `AuthorsView`, `SeriesView`, `GenresView`,
  `SearchSuggestView` (прямые запросы), `hello` (дашборд: счётчики, график
  жанров, новые, случайная, популярные, рейтинги).
- Контекст-процессор `sopds_web_backend/processors.py` — на каждой странице:
  глобальный `Counter`, случайная книга (смещение в нефильтрованном
  `Book.objects`; ловит только `DoesNotExist` — при фильтрации нужна защита
  от `IndexError`), последние книги полки.
- Сервисы `opds_catalog/services/` (`book_services.search_book` и реестр
  поиска, `paginated_book_content`, `catalog_services`, `genre_services`,
  `series_services`, `authors_services`) — общая точка для большинства
  списков: им добавляется обязательный аргумент `user`.
- Telegram: `telegram_search.search`, `author_screen`, `series_screen`;
  рассылка новых книг в канал (`fb2parser_web/autosync_hooks.py`) —
  только книги библиотек с `library_public`.
- `fb2parser_web/views.py` `statistics` и Django admin — только staff,
  фильтр не нужен (администратор видит всё).

### Счётчики
Модель `Counter` — глобальная (заполняет сканер). Для суперпользователя —
как сейчас; для остальных — счётчики по видимым книгам, считаются на лету
(для ~7 тыс. книг в SQLite это миллисекунды) с кэшем на пользователя,
сбрасываемым после скана/загрузки/изменения доступа.

### Ловушки
- **Объекты `Feed` общие для всех запросов** (создаются один раз в
  `urls.py`), `SOPDSBaseFeed.__call__` кладёт `self.request`, а gunicorn
  работает потоками: пользователь, взятый из `self.request` в `items()`,
  может оказаться пользователем соседнего запроса. Пользователя передавать
  через `get_object(request)` → `obj`.
- OPDS узнаёт пользователя в `sopds_auth_validate` (сессия или Basic с
  паролем для читалок); при `SOPDS_AUTH = False` пользователь — аноним
  (правило видимости выше).
- Полка (`bookshelf`) и «читаю сейчас»: книги, к которым доступ отозван,
  скрываются фильтром, записи полки не удаляются (вернётся доступ — вернутся).
- Сейчас OPDS и веб не исключают логически удалённые (`avail = 0`) —
  `visible_to` исключает их везде.

## Загрузка книг пользователями («приёмник») — эскиз

Полный fb2parser пользователю не отдаётся: у него глобальные настройки
(`genres.xml`, списки имён, `app_settings.json`), он работает с папками
сервера, переносит и удаляет файлы, компилирует книги разных владельцев.
Вместо него — конвейер на том же ядре:

1. **Загрузка** в личную входящую папку `inbox/<user_id>/` (вне `root_lib`).
   Проверки: квота, `upload_max_file_mb`, формат (`mime_detector`), защита
   от zip-бомб (`MAX_BOOK_FILE_SIZE`), имена членов zip без обхода путей,
   безопасный разбор XML (без внешних сущностей), имена файлов без
   управляющих символов (баг №162).
2. **Разбор** фоновой задачей: регенерация (6 проходов) по входящей папке
   пользователя; глобальные данные — только чтение. Очередь общая,
   одна задача за раз (регенерация тяжёлая — см. `MemoryError` при двух
   параллельных прогонах Test2).
3. **Упрощённая проверка** пользователем: автор, серия, номер, жанр (из
   дерева, не свободный текст), название — правка до попадания в библиотеку.
4. **Подтверждение:** поиск дубля по `origin_sha256` по всей библиотеке →
   либо добавить владение к существующему файлу, либо синхронизация в общее
   дерево с записью владельца; затем точечный скан.

За администратором остаются: компиляция, глобальные данные (жанры, имена),
правка книг с несколькими владельцами. Перед этапом 3 — отдельный детальный
проект этого раздела.

**Уточнено 2026-10-22** (подробно — `docs/multiuser-plan.md`, этап 3):
только FB2 и FB2.ZIP; синхронизация — только когда готова вся загрузка;
пользователь может собрать свои тома серии в сборник (тома заменяются
сборником, только его собственные тома); о чужих книгах пользователь не
узнаёт — ни из дублей, ни из совпадения имён, ни из подсказок. Приоритет
низкий.

## Этапы

1. **Владение и фильтр везде.** Модели (`LibraryFileOwner`, `book_owner`,
   `LibraryShare`, поля `UserProfile`), `visible_to`, помощник
   `get_visible_book_or_404`, `user` во всех сервисах, исправление всех мест
   из инвентаризации, перенос владения во всех операциях fb2parser,
   миграция (все файлы → администратор, `library_public = True`), команда
   сверки. Внешне ничего не меняется.
   Тесты: на каждый адрес из инвентаризации — «чужая книга: 404 / нет в
   списке / не в счётчике», «своя и общая — видна», «администратор видит
   всё»; перенос владения при синхронизации, сжатии, переименовании,
   компиляции (группы по владельцам).
2. **Совместный доступ:** выдача/отзыв на странице пользователя, раздел
   «Мне доступно» в веб и OPDS, переключатель «открыта всем».
3. **Приёмник** — после отдельного детального проекта.
4. **Инструменты администратора:** квоты (раздел настроек + личные лимиты),
   журнал загрузок, поиск по загрузившему, изъятие книги у всех владельцев.

## Отображение чужих библиотек

Только раздельно: «Моя библиотека» и отдельный раздел на каждую доступную
чужую библиотеку («Библиотека Ивана») — в веб и в OPDS. Общего списка
«всё, что мне доступно» нет. Следствие для правила видимости: кроме
`visible_to(user)` (всё доступное — для проверки доступа к книге по id)
нужен `visible_to(user, library_owner)` — книги одной библиотеки для
списков, поиска и счётчиков внутри раздела.
