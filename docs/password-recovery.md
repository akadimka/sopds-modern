# Восстановление пароля — предложения

Статус: **идея, к реализации не приступали**, решение отложено
(обсуждение 2026-10-07). Записано, чтобы вернуться позже.

## Задача

Пользователь (читатель, которому администратор завёл аккаунт) забыл
пароль и должен восстановить доступ сам, без администратора. Желательно
бесплатно, но надёжно.

## Варианты

| Вариант | Цена | Надёжность | Минусы |
|---|---|---|---|
| **Telegram-бот** (бот уже есть, аккаунты к нему привязываются) | бесплатно | высокая, мгновенно | только для привязавших Telegram |
| **Почта через свой ящик Яндекса/Gmail** (SMTP + «пароль приложения») | бесплатно | высокая, письма не в спам | нужен отдельный ящик и email у пользователей |
| Почтовые сервисы рассылок (Brevo, Mailjet, SMTP2GO) | бесплатно до 200–1000 писем | хорошая | подтверждение своего домена; бывают ограничения для пользователей из РФ |
| Свой почтовый сервер на сервере | бесплатно | **плохая** | без SPF/DKIM/обратного DNS письма в спаме, домашние IP в чёрных списках — не советуется |
| Резервные одноразовые коды при создании аккаунта | бесплатно | средняя | люди их теряют |
| Контрольные вопросы | бесплатно | **плохая** | ответы легко угадать — не советуется |
| Сброс администратором | уже есть | — | не самообслуживание; остаётся последним средством |

## Предлагаемая схема

**Один механизм сброса — два способа доставки ссылки.** Сам сброс —
стандартный механизм Django (`PasswordResetTokenGenerator`,
`PasswordResetConfirmView`): одноразовая ссылка с ограниченным сроком,
перестаёт работать после смены пароля. Свой механизм не изобретаем —
меняется только канал доставки ссылки.

1. **Telegram (основной).** На странице входа «Забыли пароль?» → логин →
   бот присылает в личку ссылку «Задать новый пароль» (действует ~30 мин).
   То же — командой `/password` боту. Ссылка уходит только в Telegram,
   уже привязанный к этому аккаунту (`sopds_web_backend.TelegramLink`), —
   посторонний, зная логин, ничего не получит.
2. **Почта (запасной).** Если Telegram не привязан, а в профиле есть email —
   ссылка письмом. Отправка через отдельный ящик Яндекса или Gmail с
   «паролем приложения» (настройки SMTP — машинно-локально, как токен бота).
3. **Администратор** — как сейчас: новый пароль в списке пользователей;
   для самого администратора на сервере — `manage.py changepassword`.

## Обязательные меры безопасности

- Одинаковый ответ на любой логин: «если аккаунт есть, ссылка отправлена» —
  нельзя проверять, существует ли логин.
- Ограничение частоты запросов сброса (по логину и по IP).
- Успешный сброс снимает блокировку входа django-axes (после неудачных
  попыток вход блокируется).
- Уведомление в Telegram «пароль изменён» — если менял не сам человек,
  он сразу узнает.

## Зависимость: HTTPS

Ссылка сброса ведёт на сайт и открывает смену пароля; пока сайт работает
по `http://IP:8008`, ссылку и новый пароль можно перехватить в сети.
Реализовать можно раньше, но включать для работы через интернет — вместе
с HTTPS (`docs/server-https-todo.md`, DEPLOY.md шаг 12a). Ссылка
строится из настройки «Адрес сайта» (раздел autosync в config.json,
`public_url`) — её нужно будет задать.

## Вопросы к решению

1. Будут ли почти все читатели привязывать Telegram? Если да — почту можно
   отложить и начать только с Telegram.
2. Если почта нужна: какой ящик завести под отправку (Яндекс или Gmail)?
   Добавить ли поле email в форму создания пользователя (сейчас email
   можно указать только в профиле)?
3. По какому адресу пользователи открывают сайт (для ссылки сброса)?
